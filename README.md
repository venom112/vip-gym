# VIP GYM — نظام خصومات المرتبات (Cloudflare Workers + D1)

نفس النظام الموجود في Claude، لكن يعمل على حسابك في Cloudflare بقاعدة بيانات D1، مع **تسجيل دخول وصلاحيات تُفرض على الخادم** (وليس في الواجهة فقط).

## ما تحتاجه
- حساب Cloudflare (الخطة المجانية تكفي للبداية)
- Node.js 18 أو أحدث (فقط لو هتشتغل من سطر الأوامر، غير مطلوب للرفع عبر GitHub)

## الحالة الحالية
- قاعدة بيانات D1 باسم `vip-gym` **منشأة بالفعل**، و`database_id` الخاص بها **مكتوب بشكل ثابت** في `wrangler.toml` هنا. لا حاجة لتعديله.
- **الجداول والبيانات الافتراضية منفَّذة بالفعل** على هذه القاعدة (بنود الخصم، طرق الحساب، الحالات...). لا حاجة لتشغيل `schema.sql` يدوياً إلا لو أنشأت قاعدة جديدة من الصفر.
- إذا أنشأت قاعدة بيانات مختلفة يوماً ما، حدّث `database_id` و`database_name` في `wrangler.toml` ليطابقا القاعدة الجديدة، ثم شغّل `schema.sql` عليها.

## الرفع عبر GitHub (الطريقة الموصى بها)

١) **ارفع محتويات** مجلد `cloudflare-project` إلى جذر مستودع GitHub (يعني `wrangler.toml` و`src` و`public` مباشرة في الجذر، مش داخل مجلد فرعي اسمه `cloudflare-project`). اجعل المستودع **Private**.
   - `.gitignore` يستثني تلقائياً `node_modules` و`.dev.vars` ومجلد `private/` (فيه `import-existing-data.sql` وبه بيانات موظف حقيقية — لا يُرفع أبداً لـ GitHub).

٢) **اربط المستودع بـ Cloudflare**: Workers & Pages ← Create ← **Import a repository** ← اختر المستودع والفرع `main`.
   - Build command: اتركه فارغاً.
   - Deploy command: `npx wrangler deploy` (الافتراضي).
   - Root directory: `/` إذا رفعت المحتويات مباشرة في الجذر كما في الخطوة ١.

٣) **أضف مفتاح الجلسات** (مرة واحدة، بعد أول نشر): Worker ← Settings ← **Variables and Secrets** ← Add ← النوع **Secret** ← الاسم `SESSION_SECRET` بالضبط ← القيمة نص عشوائي طويل (٣٢ حرفاً فأكثر). ثم Deployments ← Retry على آخر نشرة ليُطبَّق.
   - بدون هذا المفتاح تظهر رسالة «لم يتم ضبط SESSION_SECRET» أو فشل عام عند تسجيل الدخول.

بعد ذلك كل `git push` على `main` يبني وينشر تلقائياً. البيانات تبقى في D1 ولا تتأثر بالتحديثات.

### ملاحظة عن اسم الـ Worker
اسم الـ Worker الذي أنشأته أول مرة في لوحة Cloudflare هو `vip-gym`، بينما `name` في `wrangler.toml` هو `vip-gym-deductions`. هذا لا يعطّل النشر (Cloudflare يستخدم اسم الـ Worker المرتبط بالمشروع، لا الحقل في الملف)، لكن إذا ظهرت مشكلة متعلقة بالاسم، اجعلهما متطابقين.

## الدخول الأول
- المستخدم: `admin` — كلمة المرور: `admin`
- **غيّر كلمة المرور فوراً** من تبويب «حسابي». يظهر تنبيه أحمر طالما بقيت الافتراضية.
- يوجد أيضاً حساب `owner` محمي ومخفي — التفاصيل في القسم التالي.
- بعدها أضف بقية المستخدمين من لوحة التحكم وحدد صلاحيات كل واحد.

## حساب "owner" المحمي
النظام ينشئ تلقائياً عند أول تسجيل دخول حساباً إضافياً إلى جانب admin:
- المستخدم: `owner` — كلمة المرور: `owner`
- دور فوق المدير: صلاحيات كاملة على كل شيء، **بما في ذلك حسابات المديرين أنفسهم**.
- **مخفي:** لا يظهر إطلاقاً في شاشة «المستخدمون»، حتى لمستخدم بصلاحيات مدير.
- **محمي:** لا يستطيع أي مستخدم آخر، ولو كان مديراً، تعديله أو حذفه أو تعطيله أو انتحال دوره عبر الواجهة. الخادم يرفض هذه المحاولات برسالة "هذا الحساب محمي" (مُتحقَّق منه باختبارات تلقائية).
- لا يمكن لأي حساب آخر أن يُنشأ بدور `owner`؛ الواجهة تسمح فقط بدوري "مدير" و"مستخدم" عند إنشاء حساب.

**غيّر كلمة مروره فوراً** بعد أول نشر (سجّل دخول باسم `owner` ثم من تبويب «حسابي»)، بنفس أهمية تغيير كلمة مرور `admin`.

**حدود الحماية — بصراحة:** "محمي" هنا يعني أن تطبيق الويب نفسه لا يملك طريقاً لتعديله أو حذفه. لكن أي شخص يملك وصولاً مباشراً لقاعدة بيانات D1 (عبر `wrangler d1 execute` أو Console في لوحة Cloudflare) يستطيع رؤية هذا الحساب وتعديله أو حذفه مباشرة من الجدول، لأنه مجرد صف بيانات. هذا الوصول محصور عادة بمالك حساب Cloudflare نفسه. لا يوجد حساب "لا يمكن إزالته تحت أي ظرف" في أي نظام حقيقي — فقط حساب لا تملك حسابات النظام العادية طريقاً لإزالته.

## ما الذي يُفرض على الخادم
- كل الطلبات تتطلب جلسة صالحة (كوكي HttpOnly + SameSite=Strict، مدتها ١٢ ساعة).
- كلمات المرور تُخزَّن مشفّرة (PBKDF2-SHA256) ولا تُرسل للواجهة أبداً.
- حظر مؤقت ١٥ دقيقة بعد ٨ محاولات دخول خاطئة.
- كل عملية إضافة/تعديل/حذف تتحقق من صلاحية المستخدم على الخادم.
- لا يستطيع مدير المستخدمين غير «المدير» إنشاء مديرين ولا منح صلاحية لا يملكها، ولا يمكن حذف آخر مدير مستخدمين.

## بدائل: الرفع من سطر الأوامر
```bash
cd cloudflare-project
npm install
npx wrangler login
npx wrangler d1 execute vip-gym --remote --file=schema.sql   # غير مطلوب، الجداول منفّذة بالفعل
npx wrangler secret put SESSION_SECRET
npx wrangler deploy
```
بعد الرفع يظهر رابط مثل `https://vip-gym.<حسابك>.workers.dev`. لربط دومين خاص: Cloudflare ← Workers ← vip-gym ← Settings ← Domains & Routes.

## التجربة محلياً
```bash
cp .dev.vars.example .dev.vars      # عدّل SESSION_SECRET
npm run db:local
npm run dev                          # يفتح على http://localhost:8787
```

## استيراد بياناتك الحالية من نسخة Claude (اختياري)
ملف `private/import-existing-data.sql` فيه بيانات موظف حقيقي (رقم هاتف)، لذلك هو مستثنى من `.gitignore` ولا يُرفع لـ GitHub أبداً. شغّله يدوياً مرة واحدة من Console الخاص بقاعدة البيانات في لوحة Cloudflare، أو بالأمر:
```bash
npm run db:import
```

## ملاحظات
- **الخطة المجانية:** الواجهة تسأل الخادم كل ٥ ثوانٍ لتحديث البيانات بين الأجهزة (تتوقف عند إخفاء الصفحة). حدّ Workers المجاني ١٠٠ ألف طلب يومياً. لو عندك مستخدمون كثيرون فاتحين الصفحة طوال اليوم، ارفع الفاصل بتغيير `setInterval(check,5000)` في `public/index.html` إلى ١٥٠٠٠.
- إرسال الواتساب لا يزال بفتح واتساب برسالة جاهزة. الإرسال التلقائي يحتاج مزوّد خدمة مثل WhatsApp Business API.
- النسخ الاحتياطي: `npx wrangler d1 export vip-gym --remote --output=backup.sql`
- تصدير Excel يستخدم مكتبة ExcelJS من cdnjs (تتطلب إنترنت في المتصفح).

## هيكل المشروع
- `src/index.js` — الخادم (API + المصادقة + الصلاحيات)
- `public/index.html` — الواجهة
- `schema.sql` — الجداول والبيانات الافتراضية
- `private/import-existing-data.sql` — بياناتك الحالية (اختياري، **لا يُرفع إلى GitHub**)
- `wrangler.toml` — الإعدادات (فيه `database_id` الحقيقي بالفعل)
